## 📌 오늘 학습 계획

1. **Filter · Interceptor · AOP 비교**
    - 각 기능의 실행 위치와 적용 대상을 요청 처리 흐름에 따라 비교한다.
    - 공통 처리 로직을 적용하는 방식의 차이를 확인한다.
    - 이후 실습에서 입력값 검증과 사용자 인증이 어느 지점에서 수행되는지 살펴볼 기준을 잡는다.
2. **JSR 303 기반 DTO 유효성 검증**
    - JSR 303의 역할과 수업에서 사용하는 검증 애너테이션의 제약 조건을 확인한다.
    - DTO 필드에 검증 조건을 선언하고, 요청을 받는 부분에 `@Valid`를 적용한다.
    - 정상 입력과 제약 조건을 위반한 입력을 전달하여 검증 실행 여부와 응답 차이를 확인한다.
3. **JWT Secret Key 생성 및 환경 설정**
    - 대칭키 기반 JWT 서명에서 Secret Key가 맡는 역할을 확인한다.
    - 실습에서 사용하는 서명 방식에 맞춰 Secret Key를 생성한다.
    - 생성한 키를 `.env` 파일로 관리하고, 해당 값이 Spring Boot 설정에 전달되는 경로를 확인한다.
4. **JWT 토큰 생성**
    - 토큰 생성 코드에서 사용자 식별 정보와 서명 키가 어떻게 사용되는지 따라간다.
    - 앞서 설정한 Secret Key를 연결하여 JWT 문자열을 생성한다.
    - 생성 결과를 확인하고, 토큰 발급 과정과 인증 요청에서 토큰을 사용하는 과정을 구분한다.
5. **JWT 기반 사용자 인증 실습**
    - 요청에 토큰을 전달하고, 서버가 토큰을 검증하여 사용자를 식별하는 흐름을 따라간다.
    - 정상 토큰과 누락되거나 유효하지 않은 토큰의 인증 처리 결과를 비교한다.
    - 실습 코드에서 인증 처리 위치를 확인하고, Filter · Interceptor · AOP 비교 내용과 연결하여 정리한다.

## 🤔 예상되는 어려움

- Filter, Interceptor, AOP가 모두 공통 처리에 사용되어 실행 위치와 적용 대상을 혼동할 수 있다.
- DTO에 검증 조건을 선언하는 것과 `@Valid`로 검증을 실행하는 지점을 연결하기 어려울 수 있다.
- `.env` 파일 작성만으로 설정이 적용된다고 생각하여, 실제 환경변수 로딩 경로를 놓칠 수 있다.
- JWT 생성에 사용하는 서명 키의 역할을 데이터 암호화와 혼동할 수 있다.
- 토큰 발급과 요청 인증을 하나의 처리로 생각하여, 서버가 언제 토큰을 검증하고 사용자를 식별하는지 놓칠 수 있다.

- DTO의 제약 조건과 요청 처리 메서드의 `@Valid`를 함께 확인하고, 조건을 위반한 요청으로 검증 동작을 확인한다.

- 토큰 발급 코드와 인증 처리 코드를 나누어 따라간 뒤, 정상·누락·유효하지 않은 토큰 요청의 처리 경로를 비교한다.
